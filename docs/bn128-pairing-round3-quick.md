# BN128 第三轮：融合 Montgomery 乘法短测（2026-09-09）

本轮基线为 `b47ef6ec31`，不是最初 BigInteger 实现；只判断相对当前版本的额外收益。
真实 TVM 短测 P50 提速 **1.39–1.42×**，耗时下降约 **28%–29%**，提升明显。
先前独立核心路径短测约 **1.30×**，综合按额外 **1.3–1.4×** 理解，不承诺服务器倍率。

## 保留的改动

`FpMontgomery.multiply` 改为 CIOS：每乘一个 32-bit word，立即约简并移动一位。
原来的 `int[17]` 乘积临时数组和 `int[8]` 输出，变成一个调用内独占的 `int[8]`。
没有对象池、跨交易缓存或修改输入数组；输入校验、子群检查、计费和超时规则不变。

令 `B=2^32`，每轮 `T'=(T+a[i]*b+m*p)/B`，其中 `a[i],m<B`、`b<p`。
从 `T=0` 开始，`T<2p` 是不变量：分子 `<2p+2(B-1)p=2Bp`。
所以约简后 `T'<2p<2^255`，八个 word 足够；最后最多减一次 p。
内层每项最大为 `(B-1)^2+2(B-1)=2^64-1`，继续用 Java long 的低 64 位和无符号右移处理进位。

## 未保留的尝试

另试过专用 Fp 平方，将普通乘积的 64 次 word 乘法变为 36 次，再独立约简。
在已融合乘法基础上，16 pair 核心路径、每版本 2 JVM × 101 样本的结果：

| 实现 | P50 ms | Mean ms |
|---|---:|---:|
| 仅 CIOS | 29.454 | 29.630 |
| CIOS + 专用平方 | 29.471 | 29.718 |

每 JVM warmup 至少 10 秒且 300 次调用；顺序为 A/B、B/A。
没有明显额外收益，已撤回。当前 `Fp2.squared()` 本身展开为 Fp 乘法，
并不调用 `Fp.squared()`；后者不能仅凭方法名认定为 pairing 主热点。
实验冻结源码、样本在本机 `build/bn128-round3-square-verify/`、
`build/bn128-round3-square-ablation/`，不进入生产路径。

## TVM 短测方法

- Apple M1 Max / macOS 26.6.2 ARM64 / Corretto 17.0.19。
- 独立 JVM，`-Xms1g -Xmx1g -XX:+UseParallelGC`，无 JaCoCo。
- 每版本 2 个 JVM，每 JVM 至少预热 20 秒且至少调用 300 次。
- 每 JVM 每尺寸 101 个正式样本，合计每版本/尺寸 202 个样本。
- 两轮版本顺序 A/B、B/A；每轮打乱尺寸顺序，八组不同非零合法输入轮换。
- 实际 TVM `CALLDATACOPY -> CALL 0x08 -> RETURN`，deadline 80ms，校验 CALL 标志和返回值。
- 共享开发机短测，不是原生 Amazon Linux / x86_64 / JDK 8 性能验收，也不确定最大稳定 pair 数。
- 原始日志、每次样本、冻结源码和环境 manifest：`build/bn128-round3-tvm-quick/`。

候选生产源码摘要（脚本按基线文件顺序计算）：
`44cb902d59b6a6e0464ed6ac60172bf2b5b5a304464c0ce67be438ddcd433314`。

## 正确性

- 原差分 73,875 项断言和完整 Fp12 摘要保持一致：
  `d57360f3621d7c4b6b52f5e66b3d349e187e5234786457f489123a486d4358f5`。
- 扩展算术测试共 2,430,282 项断言。新增 100,000 对随机原始 Montgomery 输入，
  加各 bit ±2 边界及接近模数的组合；直接按 `a*b*R^-1 mod p` 核对输出，
  不借用实现自身 encode/decode 验证自己，同时检查平方别名输入、长度和操作数不变性。
- 5 个独立 JVM 初始化顺序检查通过。
- Corretto 17.0.19 ARM64、Corretto 8u442 x86_64 均通过上述差分、扩展算术及初始化检查；
  JDK 8 x86_64 通过 Rosetta 运行，只用于兼容性验证，不代表原生 Linux 性能。
- 本轮重新运行 8 个 JUnit：3 个 crypto、5 个实际预编译测试（包括 49 个外部已知答案向量），全部通过。
- 这些是回归证据，不替代独立审计或新旧节点交叉出块、历史回放兼容性验证。

## 复现

在平台要求的 JDK 下运行，脚本会创建新输出目录，不受 Gradle 测试 UP-TO-DATE 影响：

```bash
python3 scripts/bn128_compare.py --baseline b47ef6ec31 \
  --tvm --engines tvm --counts 4,16,32 --samples 101 --forks 2 \
  --warmup-seconds 20 --minimum-warmup 300
```

本机先构建回归测试及 classpath，然后加
`--classpath-file actuator/build/bn128-benchmark-classpath.txt` 复用这次构建；
各版本的 crypto 冻结源码仍分别编译，并放在 classpath 首位。
