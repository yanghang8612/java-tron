# BN128 Pairing 优化实测（2026-09-09）

本次保守优化在不同有效非零点输入上，最高测得约 **1.90 倍**的 TVM 执行速度，
32 pair 的 P50 从 **532.67ms 降到 279.89ms**，耗时减少约 **47.5%**。
主测中 **P99 ≤ 80ms 的最大采样点**从 **3 pair 提升到 7 pair**。
8 pair 的 P50 已低于 80ms，但 P99 为 84.38ms，603 次中发生 16 次超时。
随后 6 pair 的独立补测出现更高尾延迟（P99 98.03ms），因此不能将 7 pair
解释成当前桌面负载下或主网节点的稳定容量。

这里的 pair 数是一次预编译调用输入中的点对数量，不是重复调用预编译的次数。
这些是本机实测值，不是主网所有服务器的绝对容量保证。

## 环境与对照

- Apple M1 Max，10 核，32GiB 内存；macOS 26.6.2 ARM64。
- Amazon Corretto 17.0.19，`-Xms1g -Xmx1g -XX:+UseParallelGC`。
- 基线：`bd2450fe063c46a201df71594f91e9f8fc4308bb` 的原始 BN128 源码。
- 两版使用相同的 TVM、预编译解码、Istanbul 计费配置和 80ms deadline。
- 每版 3 个独立 JVM；每 JVM warmup 至少 30 秒、至少 300 次调用。
- 每个 pair 数、每个实现有 201 × 3 = **603 个正式样本**。
- 主测 9 个 pair 数，随后补测 2、6 pair；合计 **13,266 个正式 TVM 样本**。
- 使用不同的非零 G1/G2 点，每组轮换 8 份输入；输入 SHA-256 在两版 JVM 间一致。
- 不同 pair 数打乱采样顺序；fork 顺序为旧/新、新/旧、旧/新。
- 计时覆盖真实 TVM `CALLDATACOPY → CALL(0x08) → RETURN`，无 JaCoCo 插桩。
- Program/mock repository 的构造在计时外；CALL 成功标志、返回字节在每次成功执行后校验。

本机同时存在其他活跃进程和内存压缩，原始样本中可见调度/GC 等造成的抖动。
所有较慢和超时样本都保留，没有删掉异常值。
短试跑中最高出现约 2.00 倍的预编译直调提速；正式结论采用长测的约 1.90 倍。

9 pair 的优化版全部超时，因此本机不能根据这些数据宣称 80ms 支持 9 pair。
7 pair 也不是零超时：6/603，约 1.0%。原版 3 pair 同样有 6/603 次超时。
中位数、P99 和“全部样本无超时”是不同标准，不能互换。

第三方背景负载会使有限样本的零超时情况不严格单调，例如少量 1、3 或 5 pair 样本
可能比某些更大输入更慢。不能据此推断更大输入反而拥有确定的安全裕量。
6 pair 的三个优化版 JVM 中，超时次数分别为 0、13、0，P50 分别约 56.80、60.01、57.56ms。
这类跨时间段的尾延迟波动需要在空闲服务器上复现排查；本报告未删去波动较大的第二个 JVM。

## 分配量

32 pair 每次 TVM 样本的平均 Java 线程分配量，按 3 个 fork 平均：

- 旧版约 **1.238GB**。
- 优化版约 **0.509GB**。
- 减少约 **59%**。

这是累计分配字节，不是峰值堆占用；这里采用十进制 GB。
分配统计包含计时外的 Program 创建，耗时统计不包含该部分。
本次针对整个优化组合压测，没有将分配量下降或提速拆分归因到每个单独改动。

## 正确性与保留的语义

生产改动涉及 `BN128`、`Fp`、`Fp2`、`Fp6`、`Fp12`、`PairingCheck` 六个类。
保留原来的完整 G2 子群检查，没有替换 BigInteger 乘法/求逆后端，也没有增加
随机化批量校验、共享缓存、线程池或新的本地库调用。

新旧实现分别在 Corretto 17 ARM64 和 Zulu 8u482 ARM64 上通过同一套 **73,875 项断言**，
完整结果摘要一致：

```text
d57360f3621d7c4b6b52f5e66b3d349e187e5234786457f489123a486d4358f5
```

摘要包含 Fp/Fp2/Fp12、G1/G2 运算以及 pairing 最终 Fp12 的全部分量。
还检查了非法坐标、非曲线点、非子群点、无穷远点、空输入、大输入及重复 `run()`。
真实预编译回归测试和既有 Istanbul BN128 Add/Mul/Pairing 计费合约测试均通过。
projective 点的 multi-Miller 和相消另有回归测试。

验证证明了这组测试和审查覆盖下的行为一致性，不等同于独立密码学安全审计。
